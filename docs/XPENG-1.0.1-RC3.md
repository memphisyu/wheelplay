# 1.0.1 RC3 播放期间尺寸稳定性

根据 RC2 实车诊断调整。用户确认 21:44–21:50 的多次服务重建包含手动断开、连接操作，不作为异常杀后台的证据。日志可确认 3722×1836 与 3840×2024 切换曾触发完整会话重建；Root 豁免、CPU 锁与服务心跳在记录中有效。

- 尺寸容差同时限制宽、高各 12% 和宽高比 7%，覆盖上述 G9 窗口变化；不恢复旧版仅按比例 20% 的策略。3840×2160 与 3722×1836、大幅同等比例放大、明显分屏切换仍需协商。保留会话可能产生少量留白。
- 已有控制器时，尺寸必须稳定等待 4 秒才重协商；新尺寸会重置等待，回到当前尺寸或容差范围则取消。初次连接仍使用短等待。
- 通知媒体命令处理后保留 START_STICKY；无媒体会话但 Web 服务仍运行时，不因迟到媒体命令停止服务。明确停止和认证失败仍停止。
- keepalive.log 增加服务启动动作、明确停止原因与 Host shutdown 原因，便于区分手动断开、认证失败和未知服务销毁。

沿用原包名及签名，versionCode 33，可覆盖 RC2；不重置用户设置。仅本地候选版，需实车验证连续音乐/视频、分屏/全屏切换、锁屏、通知按钮以及明确停止行为。
