# 1.0.2 RC1：连接修复与可选 mDNS 本地域名

基于正式版 1.0.1，选择性引入四项上游修复，不迁移 Jetpack Compose 设置界面或整套双语资源。

## 上游修复
- beadd44：蓝牙 RFCOMM 接收队列腾出空间后唤醒读取线程，避免接收等待停滞。
- b72773d：Android 16 的 Wi-Fi P2P 安全类型报告 UNKNOWN 时按原有 WPA2-PSK 假设处理并记录诊断；仍需核对真机安全配置。
- 191c8e7：正确透传无状态码的 WebSocket 关闭帧，避免 Kotlin 非空检查触发 NPE，确保连接释放和重新连接。
- bd941a4：复用连接页时从持久设置重新读取无线模式和热点参数；切换后端先释放旧连接，避免旧 P2P 组阻碍开启系统热点。

## a6af3cd 的独立适配
核心 mDNS 公告功能可以独立引入，本版将设置接入现有 View 界面，无需 Compose。新增「设置 → Web 监听 → 启用 mDNS 本地域名」及名称输入。默认关闭，名称默认为 wheelplay.local；开启后可尝试 http://wheelplay.local:8080（以实际 HTTP 端口为准）。不同安卓设备建议使用不同名称，例如 phone.local / tablet.local。

与上游原始实现相比：
- 保持可选开关和独立偏好，不覆盖原 Web 域名、HTTPS 证书、监听端口或认证资源。
- 所有公告创建、更新、关闭均在单一后台线程串行处理，避免网络关闭/告别广播阻塞界面。
- IP、名称或 HTTP 端口变化后撤销旧公告并发布新公告；关闭期间迟到的创建结果也会清理。
- Wi-Fi 多播锁随每个公告创建与关闭；网络不具备可公告地址时不持有公告资源。
- 排除 VPN、移动网络、iPhone 的 P2P 和 Tesla 兼容地址；失败可重试，不影响原 HTTP/IP 访问。

车机必须支持 .local 解析，热点还需允许多播；此功能不保证每台车机可用，也不提供固定 IP、低端口映射或可信 HTTPS。浏览器麦克风仍使用原来的受信任证书域名，不应将 .local 当作原公网域名的替代品。
